# GeoModel3D 0.26.1: diagnose interrupted device checks

The device page could report only “Load failed”, and its visible download progress was not saved. Reopening a page after an abrupt interruption therefore lost the last observed loading stage. This patch makes failed and interrupted attempts useful for diagnosis without claiming that the underlying loading problem has been resolved.

## Changes

- Preserve structured stage, error name/message and a safe relative resource identity through the worker and client. Fetch and response-body failures retain their actual failing resource; the last progress file remains a separate observation when downloads overlap.
- Save bounded progress observations at stage/file transitions and throttled intervals. A checkpoint records its observation time and monotonic elapsed time, not a successful latency sample.
- Restore old records without restarting inference. A recovered running entry uses recovery time separately from the unknown interruption time; new runs retain their own app version.
- Exclude raw signed URLs, arbitrary payload fields, image bytes and stack traces from diagnostic fields. Keep image/protocol checks and project isolation.

## Evidence boundaries

Apple WebGPU preflight establishes that the page can obtain an adapter. It does not establish model loading, worker support, inference speed or memory suitability. A per-buffer limit is not total available GPU memory. A generic fetch error or a reopened page cannot establish an out-of-memory cause.

The forty-image study, model revision/dtypes, prompt, prepared images, quality/compatibility token caps and no-automatic-retry policy remain frozen. The earlier CPU and software-WebGPU records remain unchanged and retain their limitations. This patch adds diagnostics, not a new model-quality or physical-device performance result.

## Validation

**657 unit tests in 54 files, 72 Playwright tests, TypeScript and the production/standalone builds pass.** The fifteen targeted benchmark UI checks also pass. The full browser run used ordinary timeouts and no retries. An initial unit run was blocked only in nine subprocess-based release tests by sandbox EPERM; the unchanged full suite passed with subprocess permission. Logs and checksums are retained in the [validation record](0.26.1-validation.json).

An actual production-worker probe intentionally aborted the required pinned `preprocessor_config.json` request. It preserved the processor-loading stage, exact relative resource, original fetch error and last progress in both export and recovery, while leaving unknown byte counts/status absent. It downloaded no weights and ran no inference. This demonstrates failure reporting on Chromium/SwiftShader; it does not demonstrate Safari inference compatibility or resolve the reported underlying failure.

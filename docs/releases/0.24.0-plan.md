# GeoModel3D 0.24.0 implementation plan

This experimental milestone evaluates small Hugging Face vision-language models on a selected core interval. It adds useful local inference and a repeatable comparison workflow before choosing a production geological model.

## Scope

- SmolVLM 256M as the initial selection and 500M as the comparison candidate, with immutable repository revisions and bounded image/token inputs.
- Describe an interval or suggest observations to check. Keep output separate from accepted logs, RQD, soundness decisions and engineering properties.
- Show the exact registered-row crop and preserve its depth/source metadata with each result. Compare both models sequentially on identical input.
- Download only after an explicit action; show progress and cancellation. Release model resources on stop, model changes and close. Cache only where browser storage is available, with no promise that a model cache makes the whole site offline.
- Export a report containing model/runtime configuration, crop metadata, output, timing and human review, excluding image bytes. No project-schema migration is needed for temporary results.
- Keep manual core-photo workflows available in the standalone HTML; disable the optional AI there with an explanation.

## Dependency decision

The maintainer agreed to a local Hugging Face VLM implementation. Transformers.js supplies image processing, tokenization and generation for the official ONNX exports. Version 4.3.2 is pinned; its ONNX dependency is overridden to the existing app version 1.31.1 so two runtime versions are not shipped. This compatibility choice must be checked with real browser inference, not inferred from mocked UI tests. Each inference runtime remains in its own worker.

The browser build excludes native Node inference. `.npmrc` skips ONNX Runtime Node's optional provider download while leaving normal dependency scripts enabled. Model code/weights use Apache-2.0 licences; model repositories remain external, on-demand downloads rather than committed binary assets.

## Reproducible model configuration

| Model | Hugging Face revision | Approximate weights |
|---|---|---|
| `HuggingFaceTB/SmolVLM-256M-Instruct` | `d039ab0d4b9311b617e8ffec1d06c8464364aeb3` | 548 MiB |
| `HuggingFaceTB/SmolVLM-500M-Instruct` | `753c1752602b5e739af7a7fa6947a635051897a3` | 774 MiB |

Both use fp32 embeddings/vision and a q4 decoder so the experiment does not require `shader-f16`. Tokenizer/runtime downloads and GPU working memory are additional. The crop is scaled without distortion and centered on a 512 × 512 gray frame; the preview/hash identify that exact input. The processor consumes one square tile without image splitting. Generation is greedy, with a repetition penalty of 1.1 and at most 128 new tokens.

## Acceptance and limitations

- Unit tests: bounded requests, fixed prompts/configuration and reproducible metadata.
- Playwright: explicit downloads, unsupported devices, errors/cancellation, safe text rendering, same-input comparison, report export, unchanged project data, desktop/mobile layout and standalone gating.
- Actual engine smoke checks: load and generate with both pinned models using the production browser runtime. Record the backend/device and distinguish this from a geological quality benchmark.
- Build, all existing unit/UI tests, version metadata and production/offline regressions must pass before commit/push and publication.
- Real core quality assessment and native iPhone Safari performance require representative photographs and that device. A generic VLM cannot establish UCS, stiffness, permeability, fracture origin or reviewed RQD from a photo.

## Validation results

615 unit tests in 50 files pass. TypeScript, the production/standalone build and all 56 Playwright checks pass. The five new AI cases cover explicit downloads, unavailable WebGPU, exact aspect-preserving input and hash, pinned model/task provenance, literal HTML-like output, unchanged project data, cancellation/stale replies, interval binding, mobile layout and standalone gating.

Browser regression inference is mocked, with synthetic photos and timings. The [mobile controls screenshot](0.24.0-local-ai-mobile.png) uses iPhone 17 Chromium emulation and no model download; it is not a native Safari inference test.

A clean `npm ci` also passes. Both pinned models completed actual local generation through the production UI, with the exact 512 × 512 padded input and the Transformers.js/ONNX versions stated above. The test uses a synthetic core drawing and a SwiftShader software WebGPU adapter, so it establishes runtime execution rather than geological accuracy or phone performance. The project remained unchanged. All five affected UI cases passed again after adding the explicit output-limit note; the tested worker asset stayed unchanged.

| Model | Load | Inference, including image/prompt processing | Generated tokens |
|---|---|---|---|
| smolvlm-256m | 14.84 s | 525.46 s | 7 |
| smolvlm-500m | 29.48 s | 1154.76 s | 128 |

256M used cached weights; 500M downloaded them. A transient HTTP 502 on the first 500M download was reported cleanly and a retry succeeded. These load times are not a controlled speed comparison. The 256M output was only “This is a drill core.” The 500M output reached its 128-token cap and included an unsupported claim about an inner structure. The final UI marks capped outputs as possibly incomplete. These results are not evidence of useful geological interpretation. Expert-labelled real-core assessment and native iPhone Safari testing remain necessary before selecting a production model.

# GeoModel3D 0.29.1: storage, grouping and release reliability

This patch addresses three findings from the review of 0.29.0 without changing project formats, geological interpretations or the Qwen evaluation protocol.

## Scope

- Tie serialized project-part text to live workspace snapshots. Discarded workspaces must become collectible, while live histories retain deduplication, collision checks and fast repeated saves.
- Build location components once and reuse their membership. Preserve rounded positions, matching borehole/CPT IDs across interpretations, moved collars, the grouping radius and transitive links. Held-out diagnostics continue to score reference boreholes; calibration continues to use one reference per physical group.
- Use the release ID returned by creation for asset uploads and publication. A newly created draft must not depend on immediate appearance in tag or list endpoints. Preserve immutable release assets, tag identity, manual drafts, retry recovery and Latest-version ordering.

## Validation

**711 unit tests in 61 files, 19 targeted production Playwright checks, TypeScript, the production/standalone builds and release metadata validation passed.** The [validation record](0.29.1-validation.json) retains source hashes, artifact checksums, logs and the corrected development fixture. The complete 81-test browser suite is enforced by the PR and main CI workflow before merge/deployment; its Actions result supplies the full regression record.

The [local diagnostic evidence](0.29.1-performance/README.md) records discarded-workspace memory, unchanged workspace bytes and warm-save behavior, and dense grouping before/after measurements with exact workloads and limits. These are software measurements, not Qwen hardware benchmarks or geological accuracy evidence.

The Qwen worker, model pin, prompts, frozen image cohort and desktop evaluation plan remain unchanged.

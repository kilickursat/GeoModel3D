# GeoModel3D 0.23.0 implementation plan

This milestone connects core photographs to reviewed borehole logs, source evidence and the existing ground model. It establishes the annotation and validation workflow needed before training a rock image model.

## Photo registration and interpretation

- Read PNG, JPEG or WebP locally and preserve a bounded PNG photograph with original-file metadata and digest where available. Show stored resolution and reject images that cannot be kept within supported limits.
- Register each straight, continuous recovered segment with a photo rectangle, known start/end depths and left-to-right or right-to-left direction. Split around missing core; never stretch recovered length across a gap.
- Assist piece logging with depth-linked cuts and source highlights. Require explicit soundness, break type, geological unit and registration review before acceptance.
- Keep drafts editable and exportable. Accepting a run creates source-backed intervals and a review snapshot; changing annotations requires renewed review. Replacing existing log intervals must be explicit.

## Recovery and RQD

- Use the full drilled run as denominator. Recovery is registered recovered length divided by run length.
- RQD is the sum of sound centerline lengths of at least 100 mm divided by run length. Explicit mechanical breaks and continuous lithology logging boundaries rejoin contiguous sound pieces; unknown breaks or soundness prevent a reviewed result. Missing core is never counted as recovered.
- Preserve photo-derived results separately from measured laboratory/in-situ properties. Show assumptions and pending review rather than an invented confidence score.
- The method follows the [USBR Engineering Geology Field Manual, volume I, chapter 5](https://www.usbr.gov/tsc/techreferences/mands/geologyfieldmanual-vol1/chap05.pdf).

## Integration and boundaries

- Preserve photos, annotations and acceptance evidence through project JSON, complete workspaces, revisions, scenarios and browser storage, using the existing deduplicated evidence image pool.
- Link accepted model intervals to highlighted photograph evidence and expose the run viewer in the Site panel.
- The present model assumes vertical boreholes and stratigraphically ordered units. It interpolates through unlogged gaps and between holes; those volumes are inferred, not observations from the photograph.
- This release does not include a trained lithology classifier, fracture-orientation reconstruction, downhole surveys, or universal predictions of UCS, stiffness, permeability or shear strength from RGB imagery.

## Acceptance

- Verify metric thresholds, mechanical joins, unsound pieces, loss gaps, review gates, overlap replacement, provenance immutability and hostile-input limits with analytical unit tests.
- Verify project/table/workspace round trips, draft resumption, scenario isolation and shared image storage.
- Run TypeScript, all unit tests, the production/standalone build and Playwright desktop/mobile/offline workflows. Inspect the new UI screenshots.
- Update package/lockfile/citation/docs to 0.23.0, commit with the requested identity, push, check CI, merge and publish verified release assets.

## Validation results

605 unit tests in 49 files pass, including 36 new kernel, persistence and draft-preservation tests. TypeScript and the production/standalone build pass. All 51 Playwright cases passed; all seven affected photo cases passed again after the final interval-merge fix. The acceptance/re-editing flow passed once more after the final-depth correction. The final test uses stable borehole IDs because preserving unaffected table rows can change imported hole order.

The synthetic 1 m drill run has 0.9 m of registered recovered core, 0.1 m missing, two 80 mm sound fragments joined at a mechanical break, a 340 mm unsound fragment and a 400 mm sound piece. It gives 90% recovery and 56% RQD. Other checks cover the exact 100 mm threshold, intact logging boundaries, right-to-left photo cuts, stale acceptance snapshots, explicit replacement, unchanged laboratory tests, a photo-first case without an invented log, archived drafts/scenarios, and correction of renamed collars. Acceptance and subsequent draft edits preserve an unrelated unfinished raw log row and an unfinished final-depth entry exactly. Only a genuine extension updates the final-depth cell.

Screenshots use generated synthetic core drawings, not real geological training data. Mobile checks use iPhone 17 Chromium emulation; physical Safari was not tested.

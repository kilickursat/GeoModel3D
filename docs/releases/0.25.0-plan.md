# GeoModel3D 0.25.0 implementation and evaluation

The previous synthetic runtime check established that SmolVLM could execute locally, but did not establish useful geological descriptions. This milestone adds a closer inspection workflow and a reproducible comparison on real published core-image patches.

## Scope

- Select a registered row or an individual piece for a local AI trial. Preserve the chosen piece, exact depth interval, parent row, direction and source-pixel bounds in the preview and version-2 report.
- Fit the selected region to the 512 × 512 model frame without stretching. Enlarge small crops explicitly; interpolation adds no observed detail.
- Use a neutral description prompt that permits non-rock and unclear inputs, without asserting that every photograph depicts drill core. This matches the prompt frozen before the real-image pilot.
- Compare pinned SmolVLM 500M and Qwen3.5 0.8B configurations on eight reproducibly selected published patches. Keep model identities masked during assistant visual scoring, then publish every paired result and its limitations.
- Preserve source credits and the benchmark images' separate CC BY-SA licence. Keep model weights and original downloaded JPEGs in the ignored cache.
- Keep model output separate from accepted logs, source measurements, RQD, soundness and engineering properties.

## Evaluation boundary

The [pilot report](../benchmarks/0.25.0-core-ai/README.md) records its frozen prompt, rubric, inputs, hashes, model revisions and complete outputs. Published class labels come from the source dataset's geologist-derived logs; the new visual evaluation is by an assistant, not an independent geologist. Eight public patches with unverified borehole independence cannot establish geological accuracy or justify changing the default model. Already cropped source patches cannot establish the gain from whole-row to piece-level inspection.

Quality inference runs locally on the Node CPU backend. Browser compatibility is a separate actual WebGPU probe; software WebGPU timing does not measure native GPU or iPhone performance. Native iPhone Safari remains untested.

## Release checks

Unit tests, TypeScript, production/standalone builds and the full Playwright suite must pass before publication. UI regression tests use mocked inference and synthetic colour fixtures to verify crop geometry, input hashes, immutable depth binding, report metadata, mobile layout and unchanged project data. Actual model runs are reported separately in the pilot evidence.

The final source passes **628 unit tests in 51 files**, TypeScript, production/standalone builds and **57 Playwright tests**, without UI failures or retries. The six targeted AI cases also passed before the final full run. Exact source/input verification and six isolated benchmark rejection checks passed. Release metadata validation produced standalone SHA256 `1dc1395a5c72416fd043337f8615c7695558f50af5ac6ab41877707314920b1e`.

[Desktop piece crop](0.25.0-core-ai-piece-desktop.png) · [iPhone-sized piece crop](0.25.0-core-ai-piece-mobile.png). Both show synthetic colour fixtures; browser capability/inference are mocked. The phone view is Chromium emulation, not native iPhone Safari.

All 16 CPU quality generations completed. The model-masked assistant review found six of eight Qwen answers and zero of eight SmolVLM 500M answers met the minimum usefulness rule. Qwen still had visual contradictions on two images and noncritical unverified claims. These are pilot-specific observations, not geological accuracy. The application model selector/default is unchanged; the full advancement gate is not established.

A separate actual Qwen probe completed 32 capped tokens in Chromium 156 using Transformers.js 4.3.2 / ONNX Runtime Web 1.31.1 on SwiftShader software WebGPU, without `shader-f16`. Hash-verified pinned model files were served locally; all browser requests stayed on localhost. It took 1,124.23 seconds for generation under shared load. This proves bounded execution, not native GPU/iPhone speed or CPU/WebGPU output parity. The truncated output is excluded from quality scoring; both the initial metadata-only failure and successful pinned retry are archived with the [browser evidence](../benchmarks/0.25.0-core-ai/webgpu/summary.json).
